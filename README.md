# 顺德寻味地图

高德底图的顺德美食地点网站。**50 家店**在地图上标注，2025 大众点评必吃榜顺德区 15 家**全部落点**，每家标明**被哪些博主探过**、**是否上必吃榜**，并附抖音 / B站直达。

打开 `index.html` 即可，无需构建、无需后端。

---

## 三个标注维度

每家店在列表卡片和详情抽屉里都能看到这三件事：

1. **品类** — 含单独一档「干蒸排骨」（容边排骨饭、滋整公、蒸四味、公司排骨饭）
2. **谁吃过** — 蓝色「探店 XX」小标；详情里展开博主名、平台、这条视频讲了什么、点进去看
3. **必吃榜** — 金色「★ 2025 必吃榜」标；没上榜的会在详情里写明「未上榜（顺德区共 15 家）」

侧栏还多了一行**博主筛选**，点某位博主就只剩他探过的店。例：`?creator=yewen` 看野文探的 4 家。

详情页顶部还有一条**来源条**，直接回答「这家凭什么在图上」：★ 必吃榜 / 点评评分 / 某某博主探过 / 高德收录 4.5 分。几样都没有的，会明写「没有公开榜单或探店记录佐证」。

## 博主信源的三种可信度

这是本项目最要紧的一条规矩——**不编造视频地址**。

| 级别 | 含义 | 处理方式 |
|---|---|---|
| 已核实 | 找到了公开的顺德探店记录（标题、播放量、合集） | 挂到店，链接指向 B站主页 / 合集 / 微博原帖 |
| 用户指认 | 店名由本人口述补充，公开检索查不到对应视频 | 挂到店，链接走平台搜索，标注「视频链接待补」 |
| 未核到 | 检索过，没有公开的顺德探店记录 | **不挂店**，在信源层写明原因 |

当前 9 位博主：刘雨鑫JASON、特厨隋坡、真探唐仁杰、品城记Video、达哥在上海、大兵饿了（B站/快手叫「大兵探店」）、庞师不是师、野文不懂吃、二百者也。

- **庞师不是师 / 野文不懂吃** 属「用户指认」：探过的店按口述录入，视频链接待补
- **二百者也** 属「未核到」：检索不到顺德开盲盒的具体店名，不挂店
- **达哥在上海** 探的两家烧鹅在视频里没报店名，只记品类不挂店

### 9 位博主之外，还有一层「其他公开探店视频」

不是所有说得出名字的探店视频都来自这 9 位。详情页「其他公开探店视频」那一栏，收的是 B 站上**标题直接点名这家店**、但不属于这 9 位的公开视频，各条都用 `view` 接口核过标题 / UP / 发布日期 / 播放量，最多留 2 条，按播放量排。索引在 `assets/more-videos.js`。

这一层不参与侧栏博主筛选，也不混进「谁吃过这家」——那栏只认收录的 9 位。

## 关于「点评必吃榜 / 美团 / 高德热度」能不能接

结论先说：**这三家都不能"直接调接口拿榜单"，但有两条能走通。**

| 数据源 | 有官方 API 吗 | 有现成 skill / connector 吗 | 本项目怎么处理 |
|---|---|---|---|
| 大众点评必吃榜 | 无。榜单不对外开放 | 无 | 公开名单人工结构化录入，带年份标注（`assets/data.js` → `MUST_EAT`） |
| 美团 | 无榜单 API。开放平台只给商家自己授权的经营数据 | 无 | 不接 |
| 高德 POI 评分 / 人均 / 营业时间 | **有**，Web 服务 API `v3/place/text` + `extensions=all` | 无现成 skill，但可脚本化 | `scripts/fetch-amap.mjs` 一条命令批量补全；已跑，50 家收下 48 家 |
| 高德扫街榜 | **无**。榜单只在高德 App 里，2025-09 上线至今没开放接口；网页版 `amap.com/saosao` 打开是首页 + 登录框 | 无 | 接不了。能自动化的只有上面的 POI 字段，界面上写「高德收录」不写「上榜」 |

### 高德怎么接（唯一能自动化的那条）

```bash
# 1. 到 https://lbs.amap.com 申请「Web服务」Key（个人开发者免费额度够本地跑）
# 2. 跑脚本
node scripts/fetch-amap.mjs 你的KEY
```

产出 `assets/amap-enrich.json`，含每家的真实 `rating` / `cost` / 经纬度 / 营业时间。核对后合并进 `assets/data.js` 的对应字段即可，前端会自动显示评分徽标。

### 为什么点评和美团做不了

必吃榜是大众点评的**内容资产**，只在自家 App / 网页展示，没有对外查询接口；美团开放平台的到店业务数据需要**商家主体授权**才能取自己门店的，拿不到"某城市榜单"。所以任何号称能"接口直连必吃榜"的说法都不靠谱——包括我。真实做法只有：公开名单 → 人工录入 → 标明年份和来源。

必吃榜 15 家已全部落点。评分只在有明确公开数值时才填（太艮堡 4.8 / 9,590 评、鳗事鱼意 4.6 / 2,356 评），其余留空，不做估算。

## 店铺实拍图从哪来

列表卡片上店名右边那一排小图、以及详情抽屉里的「实拍」，点开能放大。

**图源有两条，不是二选一，是叠加的**：高德相册的食客实拍排在前面，不够 4 张时用 B 站探店画面补齐（一家店只有 1 张太单薄）。灯箱里每条都标了来源，能分别跳回 POI 页或原视频。

| 来源 | 脚本 | 现状 |
|---|---|---|
| 高德地图 POI 相册（食客评价图、商家图） | `scripts/fetch-amap-photos.mjs 你的KEY` | 已跑，50 家里 46 家有图，共 69 张 |
| B 站探店视频封面（博主实拍，可顺着 BV 号核对） | `scripts/fetch-photos.mjs` | 已跑，31 家有图，用来补齐 |

合并后 49 家店共 131 张，只剩滋整公干蒸排骨饭一家没图（高德相册只有门头、店内、霓虹灯牌，没有菜品图，按「只留菜品」的规矩没放）。

### 每店 1~3 张，是接口上限

高德开放平台的 `place/text`、`place/detail`、`place/around` 三个接口都实测过，每家 POI 固定最多返回 3 张相册图；这 3 张里通常还有一半是门头、菜单牌、店内空景，筛完平均每家 1.5 张。「每店 3~6 张」这个目标达不到，不是没筛。

### 图是同品牌其他分店时会标出来

4 家 POI 匹配到的是同品牌另一家门店：菜品形态一致，但毕竟不是本店。这些记录带 `branch` 字段，抽屉说明和灯箱底部都会写「图为同品牌「XX店」，不是这家门店」，不冒充本店实拍。

| 店 | 图实际来自 |
|---|---|
| 民信老铺（华盖路店） | 双皮奶博物馆店 |
| 顺德人家（太艮路店） | 黄金商业广场店 |
| 红星光发煲仔饭（总店） | 文海店 |
| 太艮堡毋米粥（锦龙路总店） | 良缘路店 |

**凤城鱼皮整组删掉了**：POI 匹配到「凤城鱼皮王金榜店」，图里招牌明明白白写着「凤城鱼皮王」。这不是分店差异，是两个招牌，放上去就是张冠李戴。这家回落到 B 站图。

灯箱底部的外链：记录里带 `poi` 的直连 `amap.com/detail/<poi>`；同一家店只要有一条带 poi，其余条目借用它；全都没有才退化成按店名搜，不会甩到高德首页。

### 为什么不直接爬点评/高德的图

实测过，两条都不通，不是没试：

- **大众点评**：`dianping.com/search/...` 直接 302 到 `verify.meituan.com/v2/app/general_page?...action=spiderindefence`，就是滑块验证页。无登录态拿不到列表页，更拿不到店铺相册。
- **高德网页版**：`amap.com/service/poiInfo` 在无登录态下返回空 body；改用无头 Chrome 点进详情，`AMap.PlaceSearch` 回调 `status='error'`（key 有域名白名单，非高德页面调不动）。JSAPI 的 key（网页里那个）也不能当 Web 服务 key 用，`restapi` 会报 `USERKEY_PLAT_NOMATCH`。

所以高德相册只能走**开放平台 Web 服务 API**，也就是上面第一条：申请一个「Web服务」类型的 Key（个人开发者免费），跑一次脚本，50 家的高德相册图就会落到 `assets/photos-amap/` 并自动生效。

### B 站那条是怎么抓的

按店名搜 `search.bilibili.com/all?keyword=<店名>`，捞页面上的 `BV` 号，再用**免签名**的
`api.bilibili.com/x/web-interface/view?bvid=` 取标题 / UP 主 / 封面原图（`pic` 加 `@640w_400h_1c.jpg` 压到 640×400）。
只留**标题或简介里明确出现店名**的那些，最多 3 条，存在 `assets/photos/<店id>/<BV>.jpg`。

门槛故意设得高：标题没写店名的视频一律不要，宁可这家空着，也不拿别人家的图冒充。所以有 20 家小店没图（早餐档、干蒸排骨这类，视频里只报菜名不报店名）。

## 「看博主视频」按钮

列表头部右侧那个按钮，**跟着当前筛选走**：筛了哪几位博主、哪个镇街，点开就只列这部分的结果。

里面按店分组，每条显示博主名 + 视频标题或备注，右侧小标签区分类型：

- 绿色「视频」= 有确切视频链接，点开直达
- 灰色「搜索」= 只有口述记录、没有确切链接，点开是平台搜索结果

点店名会关掉弹层、直接跳到那家店的详情和地图位置。

> 补记：这个按钮原来是纯装饰（`.sort-btn` 没绑任何事件），点了没反应，已修。

## 导航按钮

三个地方都能一键跳高德，全部走**关键词搜索**而不是坐标定位：

| 位置 | 样子 |
|---|---|
| 左侧店铺卡片右上角 | 红色「导航」小胶囊，不用点开详情 |
| 地图标注弹窗 | 「高德导航」 |
| 详情抽屉 / 必吃榜卡片 | 「高德导航」 |

链接是 `uri.amap.com/search`，PC 端会 302 到 `ditu.amap.com/search` 直接出结果页，手机端 `callnative=1` 唤起高德 App。

**搜索词是精简过的**，只用「主店名 + 镇街」，比如：

- ✅ `民信老铺 华盖路店 大良`
- ❌ `民信老铺 华盖路 双皮奶 大良 顺德 老字号`（原来的 `kw` 字段塞了描述词，高德对这种长串经常返回空）

长店名像「鳗事鱼意 · 活鳗现烤专门店 · 嘉信店」会砍到主名「鳗事鱼意」再补镇街。50 家的搜索词最长 15 字。

## 按离我远近找店

筛选区下面那条「定位我的位置，按远近找店」：

- **两种出发点**：点左边按钮用浏览器定位（页面必须是 https，手机上会弹一次权限框）；
  不想开定位、或者微信内置浏览器把定位挡了，就点右边「地图上选」，
  在地图上点哪算哪。手机上会自动切到地图那一栏，底下有一条提示，点「取消」可以退出。
- **定位成功之后**：地图上多一个蓝点「我的位置」，列表每张卡片显示「距你 X km」，
  顶部换成「离我最近」开关 + 不限 / 2km 内 / 5km 内 / 10km 内 四档；
  选了距离档，地图上还会套一个虚线圆圈，一眼看出筛的范围。详情页「去之前」那块也写着距离。
- **算的是直线距离**：两点之间的球面大圆距离，不是路线长度，也不含开车时间。
  实际怎么走点详情里的「高德地图导航」。
- **位置只存在本机**：写进浏览器的 localStorage，不上传、不发给任何服务；下次打开接着用。
  按右上角那个 ✕ 就清掉，地图上的蓝点和列表里的距离一起消失，列表回到按街区排序。
- 定位失败（拒绝权限、超时、http 页面、微信 webview）不会卡住，会直接切到「地图上选」。
- 人在顺德以外时照常能用，只是顶上的小字会写「你现在离顺德约 X km」，
  这种情况下 2/5/10 km 很可能一家都筛不出来，空列表里会告诉你最近的一家有多远。

## 地图方案

用的是 **Leaflet + 高德瓦片**，不需要申请 Key 就能跑。

- 瓦片连续失败会自动退回 OpenStreetMap，不至于白屏
- 标注带聚合（markercluster），大良那种密集商圈不会糊成一坨
- 坐标分两种：有公开经纬度的（如润记宵夜）直接用；其余是**街区级近似**，详情里会写明「这家没有公开的精确门牌坐标」。所以每个「导航」按钮走的都是**高德关键词搜索**而不是精确坐标，避免偏个几百米把人带沟里
- 首屏固定在大良—容桂核心区，不 fit 全部 50 家（跨六个镇街，fit 出来会缩到广州去）；筛选后才跟随结果
- 点任意一家店，地图直接拉到 **17 级街道**，并在那个点上打一圈会呼吸的蓝色光圈 + 店名条；抽屉占着右边一条，落点会自动挪到剩下那块的正中，不躲在抽屉底下

## 视频链接的诚实说明

每条 `visited` 记录按链接成色分三档，界面上如实标出来，不混着当「视频」：

| 标签 | 含义 | 怎么判定 |
|---|---|---|
| 视频 | 就是那一条视频 | URL 含 `/video/BV` 或 `douyin.com/video/` |
| 主页合集 | 落到 UP 主页或合集，不是单条 | URL 含 `space.bilibili.com` / `lists` / `collectiondetail` |
| 链接待补 | 只有口述记录，链接是搜索页 | URL 含 `/search` |

判定逻辑在 `assets/data.js` 的 `urlKind()`，加新记录不用手动标。

**双平台入口**：每条记录右侧固定两个按钮 —— `B站` 和 `抖音`，点哪个就在哪个平台搜「博主 + 店名」。不搞二选一，两边都留着。

> 为什么只给搜索页、不给博主主页链接：抖音 / 快手的账号 ID 没法确证，
> 拼一个 `/user/xxx` 出去就是假链接，点开 404 比给搜索页更坑人。

## 怎么把「主页合集」补成「单条视频」

B 站的空间页是纯前端渲染，`curl` 拿到的只是空壳（不到 11 KB）。正确姿势是先用无头浏览器渲染再取：

```bash
chrome --headless=new --disable-gpu --virtual-time-budget=14000 --dump-dom \
  "https://space.bilibili.com/<UID>/video" > space.html

# 空间内精准搜索（比翻页靠谱，能直接定位到历史视频）
chrome --headless=new --disable-gpu --virtual-time-budget=14000 --dump-dom \
  "https://space.bilibili.com/<UID>/search?keyword=双皮奶" > s.html
```

从渲染后的 DOM 里捞出 `BV[0-9A-Za-z]{10}`，再逐个查标题核对：

```bash
curl -s "https://api.bilibili.com/x/web-interface/view?bvid=BVxxxx" 
```

**`view` 接口不需要 wbi 签名**，直接返回 `title` / `pubdate` / `duration` / `stat.view`。
（`/x/web-interface/search/type` 那种才要签名，会 412，别碰。）

核对三件套：标题里有没有店名、时长对不对、播放量对不对。三项全中才算认领，缺一项就别挂。

抖音这边没有对应路子：静态抓不到、分享页要登录态。只能靠人工刷到后把链接填进 `visited[].url`。

## URL 参数

- `?view=must` 直接打开必吃榜
- `?creator=yewen` 按博主筛选（可选：liuyuxin / tangsui / tangrenjie / pinchengji / dabing / pangshi / yewen）
- `#shop=minxin` 直接打开某家店（可分享单店链接）

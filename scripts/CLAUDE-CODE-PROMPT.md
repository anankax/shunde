## 硬性规则（违反任何一条，结果我全部作废）

4. **发布时间以平台显示为准**，不要用视频里提到的日期（比如视频里说"上周去的"不算）。
5. **不要把"某网红探过"这类二手文章当证据。** 必须落到具体账号 + 具体视频。
6. **区分 confidently / probably。** 标题里明确出现店名 = confidently；只能从画面或评论区推断 = probably；只有区域没有店名 = 不算。

## 实操建议（省时间）

**B 站：能做，优先从这里突破**
- `https://space.bilibili.com/<UID>/lists` 这个合集页可以直接抓，能拿到合集名、条数、每条标题和发布日期。大兵饿了（B站号名「大兵探店」）就是这么查到的。
- 每位博主的 UID 用搜索或 `search.bilibili.com` 反查。
- **空间页是纯前端渲染，`curl` 只能拿到不到 11 KB 的空壳。必须走无头浏览器：**
  ```bash
  chrome --headless=new --disable-gpu --virtual-time-budget=14000 --dump-dom \
    "https://space.bilibili.com/<UID>/video" > space.html
  ```
- **更精准的是空间内搜索**，能直接定位历史视频（首屏只加载最近 30~40 条，老视频要靠这个）：
  ```bash
  chrome --headless=new --disable-gpu --virtual-time-budget=14000 --dump-dom \
    "https://space.bilibili.com/<UID>/search?keyword=<URL编码的店名>" > s.html
  ```
  在渲染后的 HTML 里找店名出现的位置，取它前面最近的 `BV[0-9A-Za-z]{10}`。
- **`view` 接口免签名**，直接核对标题/时间/播放量：
  ```bash
  curl -s "https://api.bilibili.com/x/web-interface/view?bvid=BVxxxx"
  ```
  返回 `title`、`pubdate`、`duration`、`stat.view`。要签名的是 `/x/web-interface/search/type`，那个会 412，别碰。
- **认领一条视频要过三关**：标题里有店名、时长对得上、播放量对得上。三项全中才算数，缺一项就标 `probably`。

**抖音：基本抓不到**
- 需要 JS 渲染 + 签名，静态抓取几乎拿不到内容。分享短链要登录态，`/user/` 主页需要 sec_uid，猜不出来。
- **绝对不要拼 `douyin.com/user/xxx` 这种链接**，拼错了就是 404 假链接。
- 可行路径只有两条：① 搜索引擎的快照/转载稿（注意时效和准确性）；② 视频标题被转载到 B 站、微博、小红书时的二次文本。
- **拿不到就如实说拿不到**，别用"根据公开信息推测"糊过去。链接一栏留 `douyin.com/search/<关键词>` 的搜索页，比编一个假地址强。

**容易踩的坑**
- 同名店多：顺德到处是"XX 排骨饭""XX 烧鹅"，必须核对是哪个镇街的哪一家。
- 榜单店和老店不同名但同源：比如"容边排骨饭"有三家店（容桂总店 / 大良三店等），视频探的是哪家要说清楚。
- 有些视频标题是"顺德第一 XX"但实际拍的是中山、江门，注意排除。
- **同一个博主不同平台不同名**：大兵在抖音叫「大兵饿了」、B站和快手叫「大兵探店」，快手词条还写作「吃货大兵」。查到内容先按视频标题和发布时间对齐，别当成两个人重复收录。
- 一条视频探多家店的，要拆成多条记录。
- **UP 主主页和视频链接是两回事**：`space.bilibili.com/<UID>` 是主页，`bilibili.com/video/BVxxx` 才是那一条。交回来的 `url` 必须是后者，别拿主页充数（本项目里已经有两条是主页，需要补成单条）。

## 拿到结果后怎么合并

Claude Code 给的 `visited.json` 是「shopId → 记录数组」。我这边合并时按这个规则：

1. 同 `cid` + 同 `url` 视为重复，跳过
2. 同 `cid` 但不同 `url`（同一博主探了两次），两条都留
3. `evidence: "probably"` 的记录，`note` 前面加「待核 · 」
4. 新发现的店先不建点，等确认坐标后再加，避免地图上出现漂移的假点
